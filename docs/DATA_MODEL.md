# Firestore Data Model

Public board content is kept separate from private per-user data. Every field
has one named writer, and the security rules in [`firestore.rules`](../firestore.rules)
encode exactly this table.

## `users/{uid}` — private user record

| Field                  | Type      | Writer                                         |
|------------------------|-----------|------------------------------------------------|
| `uid`                  | string    | Client, once, at registration (= auth uid)     |
| `firstName`            | string    | Client, once, at registration (1–50 chars)     |
| `lastName`             | string    | Client, once, at registration (1–50 chars)     |
| `role`                 | string    | Client, once: `student` / `instructor` / `other` |
| `registrationDateTime` | timestamp | Server (`FieldValue.serverTimestamp()`)        |

- **Read:** owner only. **Create:** owner only, exactly these five fields.
- **Update / delete:** denied — the registration timestamp can never be reset.
- `role` is descriptive only; it never grants permissions.

## `users/{uid}/prefs/{doc}` — private preferences

Reserved for the Opt-In Notifier spice. Owner read/write only.

## `messages/{msgId}` — public board

| Field        | Type      | Writer                                                   |
|--------------|-----------|----------------------------------------------------------|
| `text`       | string    | Author at create; author on update (1–500 chars)         |
| `authorUid`  | string    | Author at create — must equal `request.auth.uid`         |
| `authorName` | string    | Author at create, copied from their user record          |
| `createdAt`  | timestamp | Server (`serverTimestamp()` at create; never changes)    |
| `editedAt`   | timestamp | Server (`serverTimestamp()` on each update; absent until edited) |

- **Read:** any signed-in user (signed-out reads are denied).
- **Create:** signed in, `authorUid` is your own uid, only the four create fields,
  valid text, `createdAt == request.time`.
- **Update:** author only; may change only `text` and `editedAt`.
- **Delete:** author only.
- Message ids are generated by the client once per composed message, and the create
  runs in a transaction that skips the write if the document already exists — so a
  double-submit or retry produces exactly one message.

## Service boundaries

| Service        | Owns                                             |
|----------------|--------------------------------------------------|
| `AuthService`  | Every Firebase Authentication call               |
| `UserService`  | Every Firestore call on `users/{uid}`            |
| `BoardService` | Every Firestore call on `messages` (CRUD + stream) |

Widgets never import `cloud_firestore` or call Firebase directly.
